# 配置、上线与回滚

后台审核基线已在生产运行。本轮 2026-10-12 补丁尚未提交或部署，未写共享数据库、发布 npm/扩展或发送真实通知；以下新增上线事项以本地验收和 verification.md 为准。

## 配置差异

| 配置 | 本版本行为 |
|---|---|
| `OPENROUTER_API_KEY` | 删除 application.yml 的明文默认回退；必须通过生产既有 Secret/环境注入，不输出值。客户端仍支持本机 `FUBB_OPENROUTER_API_KEY` 回退 |
| `PREVIEWSHIP_ZIP_DIR` | 延用既有暂存目录；私有快照放其 `content-risk-inputs/`。多 Pod/重启必须访问同一持久卷，不能使用容器私有 `/tmp` |
| `PREVIEWSHIP_CONTENT_RISK_BACKGROUND_LEASE_SECONDS` | 新增，默认 180 秒，范围 60–900 |
| `PREVIEWSHIP_CONTENT_RISK_BACKGROUND_BATCH_SIZE` | 新增，默认每轮 2 条，范围 1–10；审核单独线程，不占用户构建额度 |
| `PREVIEWSHIP_CONTENT_RISK_WEB_RISK_ENABLED` | 仍为可选 Google 引用检测，可保持 false；不关闭本地规则或 OpenRouter |
| 模型、48,000 字符输入预算、三轮/15/60 秒重试及通知配置 | 延用现有配置；没有为了发布成功率把 UNKNOWN 改 PASS |
| Console 构建 `INDEXNOW_ENABLED` | 本地验收显式 false；生产沿原发布策略设置 |

没有新增“关闭审核并放行”的开关。新后端默认对普通新发布执行后台审核；历史记录不回填。撤销每 15 秒独立调度，失败退避最长一小时并持续恢复；连续失败第三次起产生固定 ERROR 信号。

## 已确定的上线顺序

1. [ ] 核对仓库/镜像版本、数据库身份、Flyway 当前至 V39、备份与回滚负责人；确认有效 OpenRouter Secret、通知配置及持久卷已挂载。
2. [ ] 按 [SQL 说明](sql/README.md) 由后端 Flyway 执行 V40/V41；确认迁移和 schema validate 成功。停止旧版消费者后再放行新发布，避免新旧任务语义混用。
3. [ ] 发布全部后端实例，确认健康、专用审核/撤销/邮件调度器正常，普通发布 `READY+PENDING` 不等待模型。
4. [ ] 发布 Console，并按 CLI → MCP → 扩展的依赖顺序构建/发行客户端。MCP 的 npm 依赖必须实际解析到包含新增字段/文案的 CLI SDK；当前只验证了本地源码构建。
5. [ ] 合成正常项目验证登录/游客/插件发布、八语言 loading/状态/手动刷新；会员 15/50/80 MiB 与月上传权益保持一致。
6. [ ] 合成风险项目验证后台隔离、全部别名拒绝、Vercel 直链或自托管目标实际撤销、真实邮件供应商受理；只用专用测试邮箱，不用真实用户内容触发。
7. [ ] 在原项目整改，先 PASS 后恢复原链接；确认迟到旧任务不影响新版本、游客不延长原期限、Abuse 永久封禁不被恢复。
8. [ ] 运行只读积压 SQL，确认纯技术故障 UNKNOWN 保持 READY 且不发违规邮件；实际模型风险未决或编码不透明则暂隔离，自动复核终结后通知整改。两个固定业务信号须被巡检捕获：`后台审核最终未完成`、`内容风险渠道撤销持续失败`。

尚未执行上述共享环境步骤。历史已经失败的部署不会被本版本自动补发；没有证据证明旧制品仍存在，也未授权批量重发，须单独核对后处理。

## 回滚边界

不得直接回滚至忽略项目隔离或不识别 `PENDING` 的旧后端。先暂停上传/新发布并保留当前安全执行器，处理已公开待审和撤销任务，再使用经过状态兼容验收的后端修复镜像。未验证旧镜像不视为安全回滚目标。

数据库保留 V40/V41，使用向前修复，不删除隔离列、撤销任务或私有输入。不得把 PENDING/HOLD 改 PASS，不得清除隔离恢复危险内容。可以独立回滚兼容旧字段的 Console，但后端仍执行访问和渠道门禁。

跨实例五秒访问缓存、已下载文件、浏览器本地副本及供应商安全名单不会保证瞬时撤回；上游暂不可用时撤销任务必须继续保留，不能假称全入口已完成下架。

## 2026-10-12 钓鱼漏检补丁上线

1. 先部署后端，由 Flyway 在已有 V41 上自动执行唯一新增 V42。禁止先手工执行 V42 再重复启动 Flyway。新增独立审计会回填仍存在的 HOLD/实际模型风险；已删除的历史制品和记录不能凭空恢复。
2. 策略默认升级 `2026-10-12-v8`，若生产显式设置 `PREVIEWSHIP_CONTENT_RISK_POLICY_VERSION`，必须同步更新。无需增大 AI 字符预算；Web Risk 仍可保持 false，不能代替本地检测。
3. 保持共享、私有且可写的 ZIP/snapshot NAS；远程恢复 journal 位于 `content-risk-inputs/restore-journal`，不能公开，也不能按普通上传临时文件提前清除。
4. 发布 Console；CLI/MCP/扩展本地构建验证不等于 npm/商店已发行，新提示随相应客户端发布才可见。
5. 用合成测试内容验收：普通发布保持快速；密码外传编码样本触发审核；模型风险未决先限制并自动复核；HIGH/SAFE 恢复当前链接，历史版不替换 current；纯技术故障不错误封禁。验收全部 net/cc 别名、源站访问守卫、供应商实际副本撤销和真实邮件受理。
6. 对已核实的三封历史投诉，使用管理页报告编号和 URL 登记入口处置；需封禁账号时明确选择“同时封禁账号”。删除或重建项目返回事实/冲突，不宣称不存在项目已经下架。既有 LOW/PASS 不会因为换策略自动批量重新扫描，历史危险站点仍需此次可信投诉处置。
7. 执行 sql/ 中三个只读验收入口，关注风险未决暂隔离、自动恢复积压、渠道严格撤销失败及报告审计。

接口 `POST /console/admin/abuse/reports/cloudflare` 使用已有管理员会话和 CSRF；参数 `reportId`（16–64 位十六进制）、`reportedUrl`（PreviewShip net/cc 单级 HTTPS 子域）、`blockUser`（默认 false）。响应 `projectId/reportId/status/knownDeleted/blocked/revocationPending`；`REVOKING` 只表示限制已设置且撤销待确认，不能当作供应商下架完成。相同报告不同站点、旧报告重放到重建项目会 409。

此入口不是开放 webhook；真实 Cloudflare 邮件自动导入尚未连接认证邮箱来源，不能直接把邮件正文或伪造的发件人当封禁指令。内容审核、自动隔离和整改邮件本身继续由后台任务执行，不需要人工审核。

回滚保留 V42 审计表、隔离守卫、撤销/恢复任务及私有 journal；禁止清空这些状态恢复危险内容。先停止新创建远程恢复副本，再处理 journal 与撤销积压，使用向前修复镜像。
