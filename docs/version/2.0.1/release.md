## 回滚边界

不得直接回滚至忽略项目隔离或不识别 `PENDING` 的旧后端。先暂停上传/新发布并保留当前安全执行器，处理已公开待审和撤销任务，再使用经过状态兼容验收的后端修复镜像。未验证旧镜像不视为安全回滚目标。

数据库保留 V40/V41，使用向前修复，不删除隔离列、撤销任务或私有输入。不得把 PENDING/HOLD 改 PASS，不得清除隔离恢复危险内容。可以独立回滚兼容旧字段的 Console，但后端仍执行访问和渠道门禁。

跨实例五秒访问缓存、已下载文件、浏览器本地副本及供应商安全名单不会保证瞬时撤回；上游暂不可用时撤销任务必须继续保留，不能假称全入口已完成下架。

1. 默认策略为 `2026-10-15-v10`；若生产显式覆盖 `PREVIEWSHIP_CONTENT_RISK_POLICY_VERSION`，同步更新。主模型沿用 `PREVIEWSHIP_CONTENT_RISK_MODEL`，新增 `PREVIEWSHIP_CONTENT_RISK_FALLBACK_MODEL` 默认 `openai/gpt-4.1`，仅作为原第二次格式/证据纠正请求，空串停用切换。沿用同一 OpenRouter key 与供应商隐私设置，不需要新密钥。须确认该 key 有主/备用模型权限和余额；备用模型单价高于 mini，调用次数和时限仍有界。
2. 核对新检查 policy_version=v10、AI 输入计划的 promptChars 与各组最大值、模型记录及 PRIMARY/FALLBACK 步骤。用合成项目验证自有账户/独立 API 通过、凭据到机器人仍限制访问；不能只核对 HTTP 200 或模型 verdict。
在途任务滚动升级：已开始的审核保留轮次及风险记忆；旧分组布局变化由保守重映射处理。同字节、零轮次、无关切且快照有效的 PENDING 发布可续接新策略，其它终态不自动重开。

3. 巡检同时检索 WARN 和 ERROR：`AI 输出校验失败`、`AI 证据校验失败`、`发布审核最终失败`、`后台审核最终未完成`。按错误码区分前置阻断、后台未闭环与真风险，不把 CONTENT_CHECK_UNAVAILABLE 一概归为网络错误。
4. 本次不批量复活历史终态、自动解除封禁或发送违规邮件。原报告 26538/26540 及所属项目在只读核对时已不存在；其余已发布 UNKNOWN 不能写成 PASS。26558 当时保留 ZIP 至首次失败后 24 小时，但有未决风险，不能直接启用技术重试或移除风险记忆；恢复需用新审核完整重判，制品到期/记录缺失则不能承诺无需重新上传。既有技术错误自助重试仍沿原入口和留存校验，公开版本不会因纯格式错误下线。

发布后的实际成功率、真实模型生产流量、渠道撤回和邮件投递仍需上线验收；本机通过不代表生产已恢复。
