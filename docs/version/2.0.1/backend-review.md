# 2.0.1 后台内容审核实现与验证

## 生产终态 PASS 仍隔离（2026-10-26）

增长版本生产验收中发现 #30970：检查 COMPLETED/PASS、MEDIUM、score=25，模型仍为 SUSPICIOUS/HIGH，三轮已终结；同一当前部署仍为 BLOCKED/CONTENT_RISK_RECHECK_PENDING、项目 quarantine。同期 #30969/#30971 为三轮 AI_UNSUPPORTED_EVIDENCE 后 UNKNOWN，亦处于暂隔离。这些是风险关切，不是已核实恶意；本轮没有打开用户制品或执行解封/重审。实际快照见 [生产验收](verification.md#2026-10-26-增长转化生产验收)。

代码可以解释 #30970 的状态组合：ContentRiskService 的评分允许有本地支持的低分 SUSPICIOUS 返回 PASS；先前风险关切只有严格降级时才改回 UNKNOWN，而旧 SUSPICIOUS 与新 SUSPICIOUS 的等级相同。自动恢复则另外要求 PASS + usedAi + SAFE + HIGH，ContentIsolationService 再次检查 SAFE/HIGH。因此本轮 PASS 没有触发恢复，旧隔离保留；记录却已经终结，不会再次被后台领取，也不满足 terminal UNKNOWN 的最终日志/通知分支。公开访问保护没有因此放开，但用户与运营可能把检查 PASS 误解成已恢复，这是 P1 状态一致性和收口缺口。

用户随后授权修复，已在本地统一该状态链路，尚未提交或部署：

- 单次与分组审核已有风险关切时，同级低分 SUSPICIOUS 保留为 `UNKNOWN/AI_RISK_UNRESOLVED`，保留风险分数和管理员证据；首次普通低分 PASS 策略不变。
- 已暂隔离版本即使各组聚合为 PASS，仍须整份制品完整 `SAFE/HIGH` 才能结束复核并恢复；否则保留关切，沿现有三轮/15、60 秒/五分钟窗口有限重试。耗尽后进入最终未决日志及整改通知流程，游客无收件人则跳过邮件。
- 用户摘要与管理列表增加衍生字段 `verifiedSafeRecheck`，仅 `COMPLETED/PASS`、模型版本非空且 `SAFE/HIGH` 为 true，不暴露模型引文。它表示安全复核结论，不表示渠道恢复完成或任务一定已入队；实际访问仍以部署状态和 URL 状态为准。
- 前端只有字段明确为 true 才显示恢复并进行有界轮询；历史缺字段或 false 的隔离 PASS 显示未决、原因与“修改后重新发布”，不提供原文件自动复抽。游客自动复核/恢复期间隐藏整改提示，八语言终态提示不再把未决称作确认风险。
- CLI、MCP 与编辑器扩展同步区分明确安全恢复、自动复核与终态未决；历史隔离 PASS 不再误报恢复，MCP 不再把已上线后隔离的未决版本描述成“尚未上线”。类型字段为可选，兼容旧后端；客户端源码与构建已验证，未执行 npm/扩展发行。
- 不可恢复的旧 SUSPICIOUS/PASS 快照按既有终态保留期清理；真正 SAFE/HIGH 恢复所需快照仍保留。

本补修沿用 v10 策略标识，不改扫描、模型、评分权重或安全恢复门槛，无新增 SQL。历史 `COMPLETED/PASS/SUSPICIOUS` 不回填、不重新排队、不自动解封；包括 #30970 在内的存量仍需整改或另行授权处置。本轮没有写生产数据或重审用户制品。回归与完整验证见 [补修验证](verification.md#2026-10-26-审核终态一致性补修本地)。ERROR 日志不能当成运维告警已经送达。

本次增长提交 `462c83d` 与上一生产 `c3becfc` 的审核、隔离、扫描、Prompt、AI Client、通知和 Worker 源码相同；生产 12 个相关主类与已验证构建逐字节一致。该证据只排除这些类的直接代码变化，不能单凭未改代码推断问题与此次流量或输入准备完全无关。

## 本模块实现

- `ContentRiskService.registerBackgroundReview` 加入发布事务，将实际 `preparedFiles` 写成私有不可变快照，并登记每部署唯一的 `PENDING` 检查；事务回滚会删除本次快照。已有同策略、同内容的有效 `PASS` 可复用，已知 `HOLD` 或未决旧轮次不能被重置为无风险任务。
- `requirePreparedForPublication` 只允许绑定私有输入的 `PENDING` 或有效 `PASS`；`requireNotKnownUnsafe` 按完整产物 hash 阻止已确认危险内容。
- 独立调度只领取新流程且部署为 `READY/SUPERSEDED` 的记录。轮次先持久化再扫描与外呼；多 Pod 通过数据库锁、租约和 `runId` 栅栏恢复。技术错误沿既有三轮、15/60 秒及五分钟窗口重试，输入缺失/不匹配保持 `UNKNOWN`，不视为安全通过。
- 领取和提交均检查预览到期及游客项目到期；即使清理器尚未把 `READY` 改成 `EXPIRED`，到期任务也终结为 `UNKNOWN`，不扫描、不隔离、不发整改邮件。非取消的后台终态 `UNKNOWN` 在事务提交后记录固定 `ERROR` 业务信号（部署 ID、错误码、轮次），供现有日志告警发现；不记录源码或供应商正文。
- 后台 `HOLD` 与隔离服务的撤销任务及整改邮件任务在结果事务内写入；审核线程不直接访问渠道。本轮实际模型风险未决改为暂隔离并有限自动复核，纯技术失败沿原在线策略；编码主动载荷超出可展开边界且命中隐藏行为时限制访问并提示提供可读代码，不伪造模型恶意结论。独立的新调用产生有效 HIGH/SAFE 可纠正未决风险，同轮修复输出不能覆盖原风险；确认 HOLD 不复抽放行。终态私有快照按安全保留规则有限批次清理，保留 `inputRef` 作为历史模式标识；硬删除、回滚留下的正式快照和中断写入留下的临时文件按安全年龄清理。
- 读取快照时对所有文件流式验完整 SHA-256；纯二进制文件仅经过 8 KiB 缓冲区，不进入后台 Scanner 的内存映射。可分析的 HTML/JS/SVG 仍完整交给既有规则，不降低 128 MiB 制品边界。后台读取与扫描和普通 Worker 共享单实例内存许可，繁忙时不领取、不扣审核轮次；完成扫描即释放许可，模型网络等待不阻塞发布构建。
- 数据库迁移为 `backend/src/main/resources/db/migration/V40__background_content_reviews.sql`；版本 SQL 目录的执行说明由版本 README / `sql/README.md` 引用该迁移。历史检查 `input_ref` 保持空，不回填或自动重审。

本轮策略默认 `2026-10-12-v8`：Scanner 只做有界静态解码，不执行上传脚本或请求外部 URL；虚拟解码来源供候选、脱敏和模型证据定位，不改变实际上传及完整内容摘要。V42 新增删除后独立安全历史，确认摘要持续拦截；实际 AI 风险及本地不透明内容的疑似记录不进入确认黑名单，可随有效复核纠正。管理页展示 `AI/LOCAL_RULES/PENDING`，避免把零候选的本地 PASS 标成 AI 低风险。

## 历史在线部署覆盖与图片请求外发（2026-10-20 只读排查）

当前后台任务从已有检查的私有 inputRef 领取，不扫描所有在线部署；V40 明确不回填历史记录。策略升级、新模型及提示词只影响实际被领取的新任务，不能让从未登记审核的存量项目自动得到审核。Cloudflare 告警邮件目前也不自动生成平台处置任务；经管理员核实后可使用既有可信报告登记入口。

`live.previewship.net` 的唯一当前部署 #14801 创建于 2026-09-08，早于 V35 审核表上线；没有任何 ContentRiskCheck 或 ContentAbuseHistory。它不是被 v10 判成 SAFE，而是未进入流程。10-20 静态核对留存 HTML 确认微软验证伪装、邮箱/密码读取、将凭据打包到机器人 URL、通过 new Image().src 发出，以及先错误提示后跳转；未执行网页或验证攻击者接口是否受理。

v10 对该原始制品本机静态回放仍只有一个 SENSITIVE_COLLECTION 候选，prompt 20,030 字符、不超预算。品牌候选目前依赖敏感 form；该站无 form。TRANSMIT、变量目标定位未覆盖图片 src 外发及这种拼接目标，本地支持的提交引用为 0。合成模型响应的反事实解析会得到 SUBMISSION_TARGET_MISSING / AI_INVALID_EVIDENCE / UNKNOWN，而不是确认 HOLD；这不是历史真实模型结果，真实风险未决仍可能触发暂隔离。

待修复边界：有界补齐历史在线部署的私有快照与审核登记；将品牌声明与无 form 的敏感交互关联；识别图片/类似 GET 请求中的敏感外发与有限 URL 拼接。新增候选不直接当恶意，不把普通图片/CDN、客户品牌、跨域身份 API 或正常登录注册一律拦截。当前条款仅记录分析和缺口，本次没有实施上述改造。生产快照与完整证据见 verification.md。
